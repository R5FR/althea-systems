## Guide de rédaction

Ce document est une **réflexion personnelle** sur votre expérience de projet. Il ne s'agit pas de décrire la solution technique, mais d'analyser votre **posture**, votre **contribution**, vos **difficultés** et votre **évolution** au sein du groupe.

### Ce que le jury évalue

- Votre capacité à prendre du recul sur votre propre rôle dans un projet collectif.
- L'honnêteté de votre analyse (une faiblesse assumée avec un plan d'action vaut mieux qu'un texte générique positif).
- La qualité de la réflexion sur les compétences développées (techniques, organisationnelles, relationnelles).
- La concrétude des exemples cités (situations réelles, pas des généralités).

### Structure recommandée

1. Introduction personnelle (contexte + rôle dominant)
2. Mon rôle concret dans l'équipe
3. Défis rencontrés et comment je les ai abordés
4. Forces et limites personnelles identifiées
5. Compétences développées
6. Ce que je referais autrement
7. Conclusion personnelle

### Conseils pratiques

> - Soyez **spécifique** : citez des situations concrètes (sprint X, bug Y, désaccord sur Z).
> - Soyez **honnête** : une limite assumée avec un plan d'action est valorisée.
> - Soyez **structuré** : titres clairs + paragraphes courts (2–4 phrases).
> - **Évitez** : description purement technique du projet — l'objectif est la réflexion sur vous.

## Rappel des critères d'évaluation (BC2.2)

| Critère | Ce qu'on attend |
|---|---|
| Réflexion sur le rôle dans le collectif | Analyse concrète de sa contribution réelle (pas du rôle théorique) |
| Identification des difficultés | Situations précises + réaction + enseignement tiré |
| Forces et limites | Honnêteté + plan d'action concret pour chaque limite |
| Compétences acquises | Trois dimensions : technique, organisationnelle, relationnelle |
| Axes d'amélioration | Propositions réalistes pour un prochain projet similaire |
| Qualité rédactionnelle | Structure claire, paragraphes courts, pas de jargon technique inutile |
